# gentar v0.11.0

gentar's verdicts mean more in this release, and less of your machine reaches a bench. A
misspelled scenario key is refused instead of silently weakening a test. The driven program's
exit status counts. A quarantined suite reads "not run" everywhere instead of pass in one place
and fail in another. A failed turn leaves a snapshot of what the pilot saw. The kit stages only
the files git would ship, and the engine refuses a subject outside its root. Most of this comes
from the ground-up review of 2026-10-19 (findings A2, A3, A4, A5, A9, B4, C2, C3, C5, D3, D4).

**Breaking:**
- The scenario schema is closed. A suite with a stray or misspelled key that loaded on 0.10.x
  is refused (exit 2) on 0.11.0, with the closest allowed key named.
- A driven program that ends with a non-zero status now fails its run.
- The kit stages only the files git would ship. A gitignored file in your working tree (a local
  `.env`, build output) no longer reaches the bench. A checkout with a `.git` that git cannot
  list is refused instead of copied whole.
- The engine refuses more subjects (exit 2, before any bench): a `subject` that is not one
  directory name inside the subjects root (a symlink to a checkout elsewhere included; it never
  resolved inside the coordinator container), and a subject whose `.git` holds a credential in
  a reflog or `FETCH_HEAD`. The kit and the engine both refuse a subject name that starts with
  `.` or `-`, which the v0.10.0 kit accepted.
- A subject suite named `smoke` or `smoke-fail` is refused. It used to run the engine's own
  self-test instead.
- File assertions match their path and `contains` text literally. `$` and backticks are no
  longer expanded by the bench's shell, and only a leading `~/` means the home directory (the
  first `~` anywhere in a path used to be replaced).

See "Upgrade, for adopters".

## What changed, and why

### The scenario schema is closed (#86)

**Problem.** A misspelled key loaded, and the scenario ran a weaker test that still passed.
`contain = "x"` in `[[verify.files]]` became a bare existence check. A `[[verify.command]]`
table (singular) was dropped without a word, leaving "0/0 assertions passed" (A2).

**Change.**
- Every table and key the engine does not read is refused, per turn type too (`send` on an
  `expect` turn), with the closest allowed key named:
  `unknown key(s) 'contain' (did you mean 'contains'?)`.
- An array of tables written with single brackets (`[verify.files]`) is refused the same way.
- The dry-run uses the engine's parser, so it refuses such a suite too.
- Every scenario in gentar, its examples and the kit template loads unchanged. So do the 68
  distinct scenario files in the known adopters' checkouts.

### The driven program's exit status counts (#87)

**Problem.** The driver waited for the command to end (EOF) and never asked how it ended. An
agent that crashed, was killed by its own `timeout`, or lost its ssh after writing half the
work could still pass on the files it left (A3).

**Change.**
- After the last turn, the driver reaps the command. A non-zero exit or a death by signal
  fails the run, and the message names the status: `timeout`'s 124, ssh's own 255 on the ssh
  tiers, a signal by name.
- Endings gentar causes are not failures: a last turn that presses ctrl-c, the danger gate's
  abort, teardown, the deadline. A SIGINT is excused only when a turn actually typed ctrl-c;
  any other SIGINT fails the run.
- A goal pilot's `done` does not wait for the program. If the program already ended on its
  own, its status counts.

### A quarantined suite: one outcome, never a pass (#88)

**Problem.** `GENTAR_QUARANTINE` wrote no report. Run directly, the suite exited 0 with nothing
to read. Through the kit, `run.sh`, which expects a report from every outcome, failed it with
"no report written" (A4).

**Change.** The coordinator prints `QUARANTINED [<suite>]: not run` and writes a report with
verdict `skip (exit 0)`, sharing the skip span's run id. The kit reads that verdict, keeps the
exit code at 0 (a known flake must not turn a run red), and ends with
`run summary: N suite(s) quarantined, not run: …`, also a warning annotation in Actions.

### A failed turn leaves a snapshot (#61)

**Problem.** A stuck TUI left only the raw transcript: no screen, no process list.

**Change.**
- When a driver turn fails (a missed pattern, the final wait, the danger gate, a goal pilot's
  end, or the exit status above), the report gets:
  - the rendered last screen;
  - the raw tail of the pty stream, with control characters made visible (a TUI waiting on a
    terminal query shows its `ESC[6n`);
  - the bench's process tree;
  - the output of a new optional `[on_failure] commands` table (strings, or
    `{ command, timeout = 1..600 }`).
- It is captured before the session closes. Every part is scrubbed, including an error that
  stopped a part from being read. The snapshot never replaces the real failure.
- A warning when a driver scenario starts its command under plain `timeout`. GNU timeout puts
  the child in a background process group, so a TUI is stopped by SIGTTIN on its first tty
  read. Use `timeout --foreground`.

### Only what git would ship reaches the bench (#92)

**Problem.**
- `run.sh` copied the whole working tree into `subjects/<name>/`. A gitignored `.env`, `.npmrc`,
  `.netrc` or build output rode into the bench, where the subject's own agent can read it (C2).
- The engine joined a scenario's `subject` onto the subjects root unchecked. A direct run of a
  scenario with `subject = "../run/secrets"` shipped the coordinator's bench key into the bench
  (C3). The kit's name check stopped that; the engine did not.
- The guard that refuses a subject whose `.git` holds a credential skipped every reflog, where
  `git pull <url with a token>` writes the token.

**Change.**
- For a checkout with a `.git` of its own, the kit stages tracked files plus the untracked ones
  git does not ignore (`git ls-files --cached --others --exclude-standard`). It never copies
  the checkout's own `.git`, `gentar/.arena` or `gentar/reports`. With `[stage] git = true`, a
  fresh `.git` without credentials is built, as before.
  - A submodule or nested repository is listed by its own git.
  - git runs with the subject's `core.fsmonitor` off and no inherited `GIT_*`, so listing a
    checkout runs nothing from it.
  - If git cannot list a checkout that has a `.git`, staging refuses.
  - The dry-run stages the same way. A checkout with no `.git` is copied whole, as before.
- The engine refuses (exit 2, with a report, before any bench) a `subject` that:
  - is not one directory name (letters, digits, dot, dash, underscore; not starting with a dot
    or a dash; not empty);
  - resolves outside the subjects root, which also refuses a symlink to a checkout elsewhere;
  - has no directory.
- The kit refuses the same names.
- The guard reads `.git/logs/**` and `FETCH_HEAD` too, in the subject, its submodules and its
  worktrees. It names the file, never the value.

### `run.sh --review --since <ref>` (#53)

`--review --since` shows what changed since a ref (the adoption, say). It reads git objects only,
is deterministic, and needs no bench. It lists:
- the changed paths outside `gentar/`;
- the executables added, removed or changed;
- the suites that mention a changed path;
- the changed paths no suite mentions.

It reports and never fails a build, and it works with a broken policy. Guide:
`docs/guides/review-an-adaptation.md`.

### Unnumbered pickers (#62)

`pick` turns recognise Claude Code's unnumbered dialogs (`❯ No, exit` /
`Yes, I trust this folder`). Before, an optional pick was skipped silently and a required one
failed "not reachable".
- An unnumbered cursor line counts only inside an aligned block of options that includes the
  label, so a prompt with typed text (`❯ git status`) never gets keys.
- A slow redraw is waited for, not read as a wrap of the list.
- A skipped optional pick is named in the report's warnings.

### Report hygiene (#85)

- **The report directory is no longer opened to everyone (D4).** Every report write ran
  `chmod 0777` on the report dir, a host bind, so any account on the host could plant or
  delete reports. The dir is never chmodded or chowned now. The report goes to the dir's owner
  on its descriptor, and `bin/arena run` makes `./out` as the user before compose can.
- **A report's subject reads `arena` again.** v0.10.0 scrubbed the bench account's name from
  the whole report and every exported span. The default account, `arena`, is also the default
  subject, so every subject was blanked for a name the docs publish. That pairing is now
  exempt; any other account name is still scrubbed.

### Smaller fixes

- **A suite named like a builtin is refused (#90).** A subject suite named `smoke` or
  `smoke-fail` used to run the engine's own self-test instead, silently (A5). It is refused now
  with "rename it", even when another file in the scenarios directory is broken.
- **File assertions are matched literally (#90).** Paths and `contains` text were quoted with
  `repr()`. That switches to double quotes when the text holds a `'`, and the bench's shell then
  expanded `$` and backticks (A9). They are quoted with `shlex.quote` now. Only a leading `~`
  means the home directory.
- **The dry-run reports `pick`, `key` and `abort` suites UNVERIFIED (#93).** It drove past a turn
  it cannot take, so the next turn timed out and the suite read FAILURES. It now replays the
  turns before the first such turn, stops, and reports UNVERIFIED. A suite with a judged
  `expect` or a goal pilot is not driven at all.
- **`bench-template/build.sh` runs the way its header says (#93).** The pin travels as its first
  argument: `ssh bench-host sh -s -- "$(cat bench-template/VERSION)" < bench-template/build.sh`.
- **Locale-proof sha checks (#89).** `mirror.sh`, `release-gate.sh`, the mirror's
  `verify-ref.sh` and `bin/bench-reap` checked hex with `[0-9a-f]`. Under a shell that orders
  ranges by locale (macOS's bash 3.2 with `en_US.UTF-8`), uppercase A–E passed. The sixteen
  digits are spelled out. Linux mirrors and runners (bash 5) were not affected.
- **`GENTAR_CI_RUNNER` docs (#59).** On GitHub Free, an organisation variable reaches public
  repositories only. Without it, `plan` falls back to `ubuntu-latest` and `checks` to every OS
  in `[phase1] os`. The kit README's list of secrets and variables is complete, held by a test.

### The docs tell the truth (#93)

From finding D3, with C5 and B4:
- **One adoption mode, the own arena.** It runs on the repo's own runner, or through the arena
  mirror for a public repo. The retired central dispatch keeps a short record.
- **Local bench mode needs no SSH secrets.** With `GENTAR_BENCH_HOST=local`, neither
  `BENCH_SSH_KEY` nor `GENTAR_BENCH_USER` is read.
- **The examples work when followed.** Delete the kit's `first-suite.toml` before copying an
  example in. The template suite no longer sets `name`, so a copy under a new file name is a new
  suite.
- **Never edit `run.sh`.** The subject comes from the scenarios (`GENTAR_SUBJECT` overrides).
  An engine bump is a re-copy of the kit from the new tag.
- **Symlinks do not survive the bind mount.** Copy or clone a checkout into `subjects/`.
- **The danger gate, as it is.** It matches about ten command patterns (`rm -rf ~` passes). The
  pilot-simulator reference says what it checks and when.
- **`sbx` is the 1.0 tier.** `tart`, `osb` and `daytona` are marked experimental wherever tiers
  are documented. On `osb`, gentar's own pty bridge drops a session that sends nothing for 30
  seconds.

## Upgrade, for adopters

1. **Check your scenarios against the closed schema first.** Run
   `GENTAR_REF=v0.11.0 gentar/run.sh --check`: it dry-runs every suite with the pinned engine's
   parser. A refusal names the file, the key, and the closest allowed key. Fix each, then
   re-pin for good. Until step 5, `--check` also reports your kit files as differing from the
   pinned kit's copy; that is expected and goes away with the re-copy.
2. **Check how your driven programs end.** A suite whose program exits non-zero after its last
   turn now fails. End such programs with a last `key` turn pressing ctrl-c, or make them exit
   0. A headless command under `timeout` that hits its limit fails with 124. A death by a
   signal no turn caused fails too, and so does ssh's own 255 on the ssh tiers.
3. **Check what your suites read from the working tree.** The kit now stages only what git would
   ship. A suite that read a gitignored file (a local `.env`, a build output) no longer finds it
   on the bench: produce it in a step, or stop ignoring it. A suite named `smoke` or
   `smoke-fail` is refused: rename it. A subject name that starts with `.` or `-` is refused:
   rename it, in every scenario's `subject` too. For a direct engine run, copy or clone the
   subject into `subjects/` (no symlink), and stage a fresh clone: a
   `git pull <url with a token>` leaves the token in the reflogs, and fixing the remote URL does
   not remove it.
4. **Check file assertions that relied on the shell.** A `[[verify.files]]` path or `contains`
   text is now matched literally. Write the literal text you expect, or use a
   `[[verify.commands]]` assertion where shell evaluation is intended.
5. **Re-pin the kit to `v0.11.0`.** Copy these from the tag, byte-identical:

   | Kit file | Changed in v0.11.0 |
   |---|---|
   | `gentar/run.sh` | pin; stages only the files git would ship; refuses a subject name starting with `.` or `-`; `--review --since`; reads a quarantined suite's `skip` verdict and lists it in a run summary |
   | `gentar/plan.py` | `stage-tree` (the staging above) and `review` |
   | `gentar/dryrun.py` | stages its workspace like `run.sh`; `pick`, `key` and `abort` suites read UNVERIFIED |
   | `gentar/release-gate.sh` | locale-proof sha check |
   | `gentar/mirror.sh` | locale-proof sha check (mirror mode only) |
   | `mirror/arena/verify-ref.sh` | locale-proof sha check (your private mirror's copy) |

   The kit workflows did not change. `gentar/README.md`, `gentar/policy.toml` and your scenarios
   are your own; the kit's README documents `[on_failure]` and `--review`. The template suite
   `gentar/scenarios/first-suite.toml` no longer sets `name`, so a copy under a new file name is
   a new suite; a suite you already copied from it is yours, and keeps working.
6. **Optional:** add `[on_failure] commands` to a driver suite whose failures are hard to read.

## Not live-proven in this release

- **The exit-status check with real agents.** The mirror's scripted suites check it only with
  scripted programs (gate runs 39863580570 and later): a clean exit passes, and the danger
  gate's abort passes. `agent-pty-smoke`, where claude exits after ctrl-c ctrl-c, runs only
  where a provider key is configured.
- **Unnumbered pickers against a live Claude Code dialog.** Tested against rendered fakes. The
  first live use is an adopter's onboarding suite.
- **A failure snapshot from a real stuck TUI.** No gate suite fails, so none has produced one;
  every part is unit-tested.
- **`timeout --foreground` in `agent-pty-smoke`.** Unverified until its next dispatch.
- **Quarantine through the mirror.** The mirror sets no `GENTAR_QUARANTINE`; unit-tested only.
- **Subject staging, the subject-name refusal and `--review` on a real subject.** The gate suites
  are subjectless, and today's nightly skipped its subject suites (no subject token). Unit- and
  dry-run-tested; the first live use is an adopter's next run.
- **A real provider key end to end**, as in v0.10.0.

## Known limits

Planned before 1.0 (the path-to-1.0 plan; both design decisions made on 2026-10-22):
- **The outcome model.** Exit 3 = inconclusive is coming. Until then, an infrastructure error
  is exit 1, like a product failure, and an interrupted run can still write a pass (A6, B1).
- **A1 outside mirror mode.** A default `evidence = "job"` release gate still accepts a sweep
  that skipped suites. The sweep manifest with `[phase2] require = "all"` comes in the next
  minor release.
- **Still open from the review:**
  - the kit's own TOML reading (A7);
  - gate suites that cannot fail (A8);
  - concurrent runs (B3);
  - the runner trust boundary (C4). Among it: the kit refuses a `GENTAR_CI_RUNNER` that
    contains `arena`, the default bench label. A repository that renames its bench label
    (agentmux uses `agentmux-lab`) is not protected by that check; until the fix, keep
    `GENTAR_CI_RUNNER` off any label your bench runner carries.
- **gentar's own bench hosts:** process command lines are visible across accounts (no
  `hidepid`). It was tried and dropped: it breaks rootless Docker's container start. Mitigated
  by v0.10.0's "no credential on a command line" and by single tenancy.
