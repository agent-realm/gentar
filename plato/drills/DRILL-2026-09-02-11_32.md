# d3-impatient — five minutes, busy machine, no reading

## What I did

Copied the quickstart block out of the README and ran it, nothing else.
`cp .env.example .env`, exported GENTAR_BENCH_KEY_FILE, built the
coordinator, ran `docker compose run --rm coordinator run smoke`.
Green: `smoke ok: Linux gentar-20260902-082532-cbbfee ...` in 26 s.
`ls out/` gave me `report-gentar-20260902-082532-cbbfee.md`; the SQL
block printed the spans table, every row pass. Five-minute budget:
met with room to spare.

## Ten seconds of poking

- `127.0.0.1:18123` answered the arena ClickHouse — my creds, my
  `gentar` db. `14318` answered the arena otelcol. Both loopback-only.
- `8123` still answered the machine's own clickhouse the whole time.
  Good.
- `4318` also answers something (404). Not mine — some other stack
  (`plato-s4-d3-otelcol-1`, wildcard bind). Left it alone.
- The dashboard: nothing published, quickstart never starts it. Ten
  seconds was up; moved on.

## Wrong turn 1 — point the knob at a taken port

I set `GENTAR_CLICKHOUSE_HOST_PORT=8123` (the native server's port) in
a copy dir and brought up clickhouse. It came up **healthy**, exit 0,
docker says `127.0.0.1:8123->8123/tcp` is published. Then I curled it
with the arena's own creds and got `AUTHENTICATION_FAILED` — the
native server was answering the port my arena claims. No error, no
warning, no failed health check, at any point. If I had actually
leaned on that publish I would have been querying the wrong
ClickHouse indefinitely.

## Wrong turn 2 — forget the project name in a copy dir

Two copy dirs with the same basename, no `COMPOSE_PROJECT_NAME`. The
second `up -d` just said `Running` — rc 0, no new container, no
warning — and `compose ps` in the second dir reports the first dir's
container as its own, one shared volume. Exactly what the README's
coexistence paragraph says happens; nothing surprised me beyond that.
One honest stumble on the way: my first port pick (18174) had been
taken by another arena mid-run and the error named the port number
only — took a grep to find which knob owned it.

## Cleanup

`docker compose down -v --remove-orphans` in every dir I created
(main worktree arena + both wrong-turn copies). Nothing of mine left
after ~65 s: no containers, no volumes, no sandbox on the bench-host
for my run id. The native 8123 server and every foreign stack were
untouched throughout.
