# gentar v0.11.1

A patch release on the 0.11 line, with three fixes. `bin/sbx-file-login` works on rootless
Docker. On the local tier, a forwarded provider key no longer makes the bench-host check refuse
every suite. A private mirror's `verify-ref.sh` no longer fails a commit it has admitted. The
scenario schema and the exit-code contract are unchanged.

## What changed, and why

### `bin/sbx-file-login` works on rootless Docker (#108)

**Problem.** The script ran its login container as `--user $(id -u):$(id -g)`. Under rootless
Docker that uid maps to a subordinate uid, so the login files were written as a stranger and the
final `chmod` failed. A local-mode bench then failed at `PREPARE IMAGE`. The kit's own refusal
on such a host tells you to run this script, from the pinned engine.

**Change.**
- It takes the daemon and the uid from `bin/docker-identity --local`, the same answer the local
  coordinator runs with: 0:0 on rootless Docker (there, the calling user), the user's own uid on
  rootful Docker.
- A daemon that script cannot identify is refused before anything is written, and so is running
  it as root on rootful Docker.
- It needs `bin/docker-identity` beside it, so run it from a gentar checkout or from the kit's
  staged engine.

### The sbx secrets check runs in a clean environment (#102)

**Problem.** Before it creates a bench, the engine runs `sbx secret ls` on the bench host and
refuses a host where sbx holds stored secrets. On the local tier the call inherited the
coordinator's environment, provider keys included. With `ANTHROPIC_API_KEY` set, sbx 0.39 prints
a note where it would print "No secrets found". The check counted that line as a stored secret,
and every suite was refused with exit 2 before any bench existed.

**Change.** The check runs under `env -i` with only what sbx reads to find its config, state and
keyring (`HOME`, the four `XDG_*_HOME` directories, `XDG_RUNTIME_DIR`,
`DBUS_SESSION_BUS_ADDRESS`, and `PATH` to find `sbx`), each passed only when set, on the ssh tier
too. A stored secret is still refused, and still reported as a count only. v0.10.1 carried this
fix; v0.11.0 did not.

### `verify-ref.sh`'s cleanup no longer fails an admitted commit (#101)

**Problem.** `git fetch` starts a detached `git maintenance run --auto` that can still be writing
into the temporary clone while `rm` removes it. Under `set -e`, the failing `rm` in the EXIT trap
became the script's status, so a mirror's gate admitted a commit and then exited 1.

**Change.** Its git runs with automatic maintenance off, the cleanup retries for up to 2 s and
runs without `-e`, and a clone that will not go is left behind with a warning while the verdict
stands.

### gentar's own pull requests are scanned (#104, #106, #107)

A required job, `scan (added lines)`, now runs `bin/pr-scan` over what a pull request to this
repository adds. It is this repository's CI: no kit file changes, and it reaches no adopter.

### Stand-in values (#105)

Comments, docs and test fixtures use synthetic stand-in values. No behaviour changes.

## Upgrade, for adopters

1. **Re-pin the kit to `v0.11.1`.** Copy `gentar/run.sh` from the tag, byte-identical; `--check`
   compares it against the pinned engine. Its one change is the engine pin,
   `REF=${GENTAR_REF:-v0.11.1}`. The other kit files (`gentar/plan.py`, `gentar/dryrun.py`,
   `gentar/release-gate.sh`, `gentar/mirror.sh`, `.github/workflows/gentar-arena.yml`) are
   unchanged from v0.11.0.
2. **A private mirror re-vendors `verify-ref.sh`** from `subject-template/mirror/arena/`.
3. **No scenario, policy or workflow change.**

## Not live-proven in this release

- The rootless fix is proven by unit tests that drive the script with a stand-in `docker`. The
  live proof is a login on a rootless bench host.
- A host where the old script already failed may hold login files owned by a subordinate uid
  under `~/.config/com.docker.sandboxes`. The new script does not remove them, and its final
  `chmod` can fail on them. Remove them first. This case was not tested.
- The sbx variable set was measured against sbx 0.39.0 only. Re-measure when the bench host's sbx
  is upgraded.

## Verification

- **Unit suite** on the release PR: 728 tests pass in the checkout layout and in the image
  layout.
- **gentar's hosted CI** on the release PR is green.

The tag `v0.11.1` goes on the release PR's merge commit, and only after that commit's own mirror
gate has been read for every suite, with nothing skipped or quarantined. That read is recorded on
the release PR.
