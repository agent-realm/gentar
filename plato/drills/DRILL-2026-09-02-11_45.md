# d1-tweaker — bend the hardened schema until it lies

## What I did

Two weeks of writing these TOMLs teaches you where the optional-looking
seams are. I scaffolded a fresh subject (`subject init tweaker-demo`),
read the emitted skeleton, and then spent the session feeding the loader
and the runner forty-odd bent shapes: empty strings, renamed keys,
wrong-typed values, nested tables, duplicated names, malformed TOML,
bogus enum values, and — my actual jackpot hunt — probes that look
filled-in but assert nothing real.

Every mutant ran through both `coordinator ls` (does it even load?) and
`coordinator run <name>` (what happens live?), each with its own
GENTAR_SCENARIOS_DIR dir mounted at /extra. Full battery logs preserved
under /tmp/gentar-s4d1-scratch/.

## The good (no event, worth saying)

The steer's fixes hold everywhere I could reach structurally:

- Renamed keys, off-schema keys (nested and top-level), malformed TOML,
  wrong-typed `steps`/`tokens`/`agent`/`subject`/`template`/`bench`/
  `name`/`verify.commands`/probe fields — ALL exit 2 with file + key +
  legal keys named, `ls` and `run` agree, zero tracebacks.
  `scenario.credentials[0] must be an env var name` even checks list
  elements.
- Empty probes: `contains = ""`, `path = ""`, `command = ""`, empty
  probe tables (`verify.commands[0] missing command`) — all refused
  with "an empty probe asserts nothing". Whitespace-only `"\n"` refused
  too.
- `[verify]` present but empty → assert guard fires at run, exit 2,
  refused-report written, no bench spent.
- `subject init --dir`: refuses held output exit 2 naming files; refuses
  `--dir` at an existing file (`cannot be created: File exists`), 70-char
  names, names with spaces/slashes — all clean exit 2; `occupied.txt`
  bystander untouched; nested `--dir` created via mkdir -p.
- Teardown settles: green run's sandbox gone from `sbx ls` at +0s and
  +65s past process exit. No linger event.
- Junk in a scenarios dir (subdir TOMLs, `.txt`, `.toml.bak`) silently
  ignored; `run <unknown>` names searched dirs + the
  GENTAR_SCENARIOS_DIR knob (the old dead end is gone).

## Findings (report-worthy events, named, with reproduction)

### F1-bench-kind-traceback — `bench = "bogus-tier"` → raw traceback, exit 1

Event: "Traceback where a usage error was owed (exit != 2 or stack dump)".
Also the ls/run divergence goal: `ls` accepts it silently (exit 0, listed),
`run` dies with a Python stack dump. The loader type-checks `bench` as a
string but never checks the value domain; `make_bench` then raises
`BenchHostError` as an unhandled traceback:

```
gentar.benchhost.BenchHostError: unknown bench kind 'bogus-tier' (known: sbx, tart)
```

via `cli.py:43 → coordinator.py:224 → benchhost.py:399`, exit 1. The text
knows the legal values — it just arrives as a stack dump instead of the
designed exit-2 ScenarioError naming the file and key. Contrast: bogus
`template` and bogus `agent` both fail late but CLEAN (named `FAIL`,
exit 1, no traceback) — only `bench` tracebacks.

Repro: scenario `[scenario]` with `bench = "bogus-tier"`, valid steps +
one probe; `docker compose run --rm coordinator run <name>` → traceback,
exit 1. Log: `/tmp/gentar-s4d1-scratch/run-b3467.log` lines 24–40.

### F2-tautology-fake-green — vacuous probes pass green, exit 0

Event: "Exit 0 (PASS) on a scenario whose probes assert nothing real".
The jackpot. Steps `['true']` (install nothing), probe:

```toml
[[verify.commands]]
command = "echo ok"
contains = "ok"
```

→ `oracle ok: 1/1 assertions passed`, exit 0, PASS report. Same green
with the files family: `[[verify.files]] path = "/etc/hostname"` and
steps `['true']` → `oracle ok: 1/1`, exit 0. Every guard in the steer
(empty strings, 0/0, stub keys) is structural; a filled-in probe that
asserts the bench's own shell (or a file every Linux bench has) sails
through. Nothing ties a probe to the subject or the steps above it.

Repro: `/tmp/gentar-s4d1-bench/b1-tautology/one.toml` and
`b2-file-tautology/one.toml`; `coordinator run b1` / `run b2` → exit 0.
Logs: `/tmp/gentar-s4d1-scratch/run-b1.log`, `run-b2b5.log`.

### F3-driver-zero-turn-green — driver suite with zero turns, zero probes passes

Event: same "Exit 0 (PASS) asserting nothing". A scenario with ONLY:

```toml
[driver]
command = "true"
```

(no verify section at all — the exact 0/0 shape the assert guard exists
for) runs the driver exemption to its vacuous limit: `driver ok: 0
turns`, exit 0, PASS report. The driver drove nothing, asserted nothing,
and its "outcome" is green by definition. The guard's driver exemption
(as recorded in SCENARIO.md) assumed the driver's outcome IS a verdict;
a driver with no turns has no outcome.

Repro: `/tmp/gentar-s4d1-bench/b5-driver/one.toml`; `coordinator run b5`
→ `driver ok: 0 turns`, exit 0. Log: `run-b2b5.log` lines 11–14.

### F4-credentials-string-letters — `credentials = "STRING"` accepted; guard demands single-letter env vars

Events: "An error message that does not name the file or the offending
key", plus silent wrong-type acceptance at load. The loader checks
credentials list ELEMENTS (`credentials = [5]` →
`scenario.credentials[0] must be an env var name`) but not the outer
type, so a bare string loads fine (`ls` exit 0). At run the credential
guard iterates the string as a list of characters:

```
Error: credential guard: scenario 'b3' needs A, N, T, H, R, O, P, I, C, _, A, P, I, _, K, E, Y — not provided (refusing before any bench exists)
```

and the refused report's credentials field records that letter list
verbatim. The message names neither the file nor that `credentials`
must be a list of env var names — a bending user's next plausible
spelling is unreachable from this text.

Repro: `[scenario]` with `credentials = "ANTHROPIC_API_KEY"` (string,
not list) + tautology probe; `coordinator run b3` → exit 2 with the
letter list. Log: `run-b3467.log` lines 5–8; report
`out/report-refused-b3-20260902-083512.md`.

### F5-empty-name-ghost-scenario — `name = ""` loads as a runnable ghost

Event: "Silent acceptance of an off-schema key (no error, no effect)" —
here: no error, AND an effect no one can see. Every other string field
demands non-empty, but `[scenario] name = ""` is accepted at load. The
scenario then registers under the empty name: `ls` prints a BLANK line
for it (invisible in an inventory), the unknown-scenario error's known
list carries a leading empty entry (`known: , agent-smoke, …`), and
`run ""` actually EXECUTES it — a bench was created and the run failed
only on unrelated subject staging (`FAIL []: local tar of
/subjects/tweaker-demo failed`, exit 1, the empty brackets echoing the
name). A typo'd name field quietly becomes a nameless runnable scenario.

Repro: `[scenario]` with `name = ""` + tautology probe;
`coordinator ls` (blank line among the suites), `coordinator run ""`.
Logs: `/tmp/gentar-s4d1-scratch/m39-name-empty.log`,
`run-m17-m39.log` line 13, `run-m39-empty.log`.

### F6-silent-name-collision-shadowing — duplicate scenario names resolve silently, loser has no effect

Event: same silent-acceptance family, at file granularity. Two shapes:

1. My dir's `smoke.toml` (name `smoke`) alongside the builtin: `ls`
   shows one `smoke`, `run smoke` runs the BUILTIN (report proves it —
   uname step, subject `arena`); my valid, parsed, schema-clean file is
   silently ignored — no error, no warning, no effect.
2. Two files in ONE scenarios dir both `name = "b9"` (a.toml, b.toml):
   `ls` shows one `b9`, `run b9` runs b.toml (`echo FILE-B-RAN` in the
   report); a.toml silently vanishes.

Nothing tells the author their file lost a name race — the old
"confusing first contact" shape, reborn one level up.

Repro: `/tmp/gentar-s4d1-bench/b8-collide-smoke/smoke.toml` mounted at
GENTAR_SCENARIOS_DIR, `run smoke` (builtin's report lands in out/);
`/tmp/gentar-s4d1-bench/b9-dup/{a,b}.toml`, `run b9`. Log:
`run-collide.log`; reports `report-gentar-s4d1-20260902-083906-39d2e9.md`
(builtin smoke) and `report-gentar-s4d1-20260902-083927-bdf817.md`
(FILE-B).

  commands, files") — the schema is narrower than the README's

  Safety property intact (refused, exit 2, nothing overwritten).

  clean named `FAIL` (exit 1, remote's own message), teardown warns
  "sandbox not found" (nothing ever existed). Bogus `template`: same
  shape, clean named FAIL at pull time.

  `ls` silently ignores it (builtin 18 only); the pointer appears later
  in `run <unknown>`'s "Searched scenarios dirs" line.
- Scenario names `"x/y"`, `"m 30"` accepted and harmless — run/report
  paths are run_id-based, not name-based.
- Empty `steps = []` / absent steps → `needs [oracle].steps or a
  [driver] command`, exit 2.
- Red run (probe `exit 3`): clean `FAIL [f1]: 1/1 assertions failed`,
  exit 1, report written, sandbox gone.
