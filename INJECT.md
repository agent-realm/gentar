# INJECT.md — make this project a Devlooper project

You are an AI coding agent (Claude Code, Codex, Gemini CLI, ...) and this file is
your instruction. The pilot dropped it here to give this project a **devlooper** —
a recorded, measured, agent-run design loop under one engine. This file is the
whole adapter: no other checkout is needed until the loop itself starts.

Devlooper is the spec — the design-time loop that decides what to build
(`github.com/loox-org/devlooper`). An **engine** is one implementation of it. Your
job ends when this project carries a `root` branch and a `DEVLOOPER.md` naming its
engine. You run no loop — ever.

## Boundaries — binding

- **You write only the `root` branch** (display form `/`; git forbids a literal
  "/" name) and the files this procedure puts on it. The default branch and every
  pre-existing branch and tag are read-only, always. The chosen engine later
  writes only its own namespace (engine-plato, for example: `refs/heads/plato/*`
  and tags `v*-rc`) — never yours.
- **You never decide values** (targets, blessing, closure) — the pilot does.
- **Report, never repair.** Not a git repo, a dirty tree, a `root` branch already
  taken — each is reported; nothing is initialized, committed over, or forced
  without the pilot's word.
- Anything the pilot defers is recorded once and never raised again.
- Count with a tool and paste the output; never do arithmetic or set comparison
  in your head. Markdown only, ATX headings, no emojis, terse. Timestamps
  `YYYY-MM-DD-HH_MM`. `INJECT.md` and `DEVLOOPER.md` keep their uppercase names —
  they are the contract.

## Execute

Print the crumb `devlooper › inject › <step> › <state>` at each report.

1. **Verify the repo.** `git rev-parse --git-dir`. Not a repo → tell the pilot and
   ask before `git init`; init only on their confirmation. Dirty tree → report it;
   proceed only if the pilot says so (`root` is cut from current HEAD, so
   uncommitted work does not ride along).
2. **Cut `root`.** `git checkout -b root` from current HEAD. If `root` already
   exists, stop and report: the project is already adapted, or the name is taken —
   the pilot decides.
3. **Survey, read-only.** Three to six lines: code (languages, entry points, build
   files), docs (README, design notes, specs), prior record (history depth, ADRs,
   earlier Devlooper artifacts). This becomes `DEVLOOPER.md`'s resources and
   context sections.
4. **Match an engine** against the survey:

   | Survey shows | Engine |
   |---|---|
   | rich existing record / docs | engine-conflux or engine-autobuild |
   | pure greenfield idea | engine-elicit or engine-plato |
   | mechanism shootout | engine-pathfinder |
   | wants fan + drillers + in-place branch-tree record | engine-plato |
   | otherwise (default) | engine-conflux (repo-per-loop), engine-plato as the in-place alternative |

   If engine checkouts exist at `~/loox-org/engine-*/`, read their `ENGINE.md`
   (read-only) to sharpen the pick; the table alone suffices when none are
   present. State WHICH and WHY in two lines — it is a recommendation the pilot
   can overrule by editing `DEVLOOPER.md` before the loop starts.
5. **Generate `DEVLOOPER.md`** from the template below, filled in, at the project
   root, on `root`.
6. **Commit to `root`.** `git add DEVLOOPER.md INJECT.md && git commit -m
   "devlooper: adapt to <engine>"`. Nothing else is staged; the default branch
   stays where it was.
7. **Hand off and stop.** The loop belongs to the chosen engine, not to you:

   ```
   devlooper › inject › done › root committed, DEVLOOPER.md → <engine>
   next › pilot: clone ~/loox-org/engine-<name> if absent, then: claude DEVLOOPER.md
   ```
