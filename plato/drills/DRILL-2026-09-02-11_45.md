# d2-tweaker drill — scoping rules mixed, on purpose

One checkout, two stacks (plato-s5-d2a from a literal `.env`, plato-s5-d2b
via `--env-file`), ports and prefix knobs moved between file, shell, and
flag until something stopped telling the truth.

## What ran

- Publish defaults: `docker compose config` with no `.env` →
  `127.0.0.1:18123`/`127.0.0.1:14318`, loopback-only. Matches compose
  comments and README.
- Silent-race claim (README "Busy Docker host?"): native macOS
  `python3 -m http.server 18177` + `docker run -p 127.0.0.1:18177:8123` →
  container Up, port "mapped", curl answered `Server:
  SimpleHTTP/0.6 Python/3.9.6` — the native listener, not the container.
  No error. Claim holds on this OrbStack host.
- Warned bend-crash, reproduced: stack up with exported port 18174 while
  `.env` says 18172 → unexported `up -d` silently recreated clickhouse
  onto 18172 (new container, no error, otelcol untouched).
- Bind-error leg, reproduced: A on exported 18174, my own blocker
  container on 18172, unexported `up -d` → old container destroyed, new
  one left `Created`, daemon bind error, exit 1.
- `--env-file` leg: `docker compose --env-file /tmp/…/s5d2b.env …` →
  project name AND ports from the env-file; coordinator container still
  reads the literal worktree `.env`.
- Live bench legs on 10.10.10.52 (all sandboxes auto-torn-down by the
  coordinator, verified): A smoke (gentar-s5d2a-20260902-083625-9beb21,
  exit 0), B-via-env-file smoke (gentar-s5d2a-20260902-083653-a9ce90,
  exit 0 — the split, see finding 2), honest-B smoke via .env identity
  (gentar-s5d2b-20260902-083750-a2ebc2, exit 0), 24-char-prefix smoke
  (gentar-s5d2a-12345678901-20260902-083827-abfbf4, exit 0).
- Prefix shape matrix through `coordinator ls` (loads Config, no bench).

## Findings

### 1. inert-publish-after-bind-fail-recovery

After the README's own warned sequence (export port → up → unexport → up
→ bind error), removing the port squatter and running plain
`docker compose up -d clickhouse` says `Started`, the container goes
`Up (healthy)` — and the host publish is silently absent. `docker port`
prints nothing, `curl 127.0.0.1:18172/ping` → connection refused; the
ports column in `docker ps` is empty. No error from compose. Only
`up -d --force-recreate` restores the publish (then `docker port` shows
`8123/tcp -> 127.0.0.1:18172` and ping answers `Ok.`). The failure mode
is the README's own silent-race class, but on the *recovery* path the
docs stop at "dies on a bind error". Reproduced twice, ~15s apart, state
stable (not a warmup artifact). OrbStack host.

### 2. env-file-identity-split

`--env-file` applies to more than ports, and the container does not see
it at all:

- `docker compose --env-file s5d2b.env config` → `name: plato-s5-d2b`,
  ports 18173/14373. So the env-file drives **project name** too —
  README's "`--env-file` … drives port *interpolation* only" does not
  hold ("only" is false).
- The coordinator container reads the literal worktree `.env`:
  `--env-file s5d2b.env run --rm --entrypoint python coordinator` →
  `prefix= 'gentar-s5d2a'`. With no `.env` at all the prefix silently
  defaults to `gentar` (verified) — no warning.
- Live: stack **plato-s5-d2b** (its own ClickHouse volume, ports
  18173/14373) ran smoke and stamped arena **A's** prefix on the shared
  bench-host — sandbox `gentar-s5d2a-20260902-083653-a9ce90`; B's
  ClickHouse holds span `run_id = gentar-s5d2a-20260902-083653-a9ce90`.
  An operator reading `sbx ls` attributes B's sandbox to A; a span query
  filtering on prefix misattributes the arena. No error anywhere.
  Docker identity from one file, bench identity from another — the
  README's scoping-rule paragraph covers ports and the literal-`.env`
  read, but not the cross-arena identity mix this produces.

### 3. bind-error-text-names-project

README: the bind error names "neither project nor env file". The daemon
error verbatim: `Error response from daemon: failed to set up container
networking: driver failed programming external connectivity on endpoint
plato-s5-d2a-clickhouse-1 (…): Bind for 127.0.0.1:18172 failed: port is
already allocated`. The endpoint name carries the project. It names no
env file, and it does not say which side of the drift (shell vs file)
produced 18172 — that half of the warning stands; the "neither project"
half does not.

### 4. prefix-docs-vs-validator

Docs (README "Lowercase-with-dashes, 24 chars max"; .env.example same)
understate the rule; the refusal message under-explains itself:

- accepted: `a`, `gentar-1a` (digits mid-name — docs never say digits are
  allowed), 24 chars exactly (`gentar-s5d2a-12345678901`, ran a full
  smoke: 47-char sandbox name, workspace dir, span run_id, report file
  all fine).
- refused, exit 2 (exit code matches docs): 25 chars, `1gentar`,
  `gentar-`, `gentar--x`, `-gentar`, `Gentar-x`, `gentar_s5`,
  `gentar.x`.
- For `1gentar` the message's own parenthetical — "(letters/digits/
  dashes, single dashes only)" — is fully satisfied, yet refused. The
  leading-letter requirement (regex `^[a-z][a-z0-9]*…`) appears nowhere:
  not in README, not in .env.example, not in the error text.

### 5. run-subcommand-recreates-telemetry

README frames the trap as "a later compose call without the exports".
The drift also bites in the other direction and through the CI
contract's own shape: with stack up on `.env` port 18172 and
`GENTAR_CLICKHOUSE_HOST_PORT=18175` exported, `docker compose run --rm
coordinator ls` — a list-only invocation — recreated the running
clickhouse onto 18175 ("Recreate/Recreated/Started", then healthy on
18175). Any invocation reconciles, not just `up`.

## Answers (goals)

- **Warned traps vs reality:** bend-crash reproduces exactly as written
  (silent recreate to file ports; and the bind-error leg destroys the
  running container first, arena left with clickhouse `Created`-not-
  running — matches). Half-applied-override reproduces and is sharper
  than written (finding 2). Error text partially off (finding 3).
- **Unnamed combinations:** finding 1 (recovery leaves publish inert,
  healthy-green), finding 2 (two identity knobs from two files in one
  invocation, live cross-arena misattribution), finding 5 (`run`/`ls`
  recreates telemetry on drift). Also: shell export silently beats
  `.env` for both port interpolation and project name per-invocation
  (`config` proof: `name: plato-s5-d2-shellwin`, published 18199) —
  README's "port knobs are `.env`-file-scoped" holds only while no
  export exists. Project knob unset → arena identity = checkout dirname
  (two checkouts both named `gentar/` are one arena — README's
  basename warning, consistent).
- **Prefix edges:** unset → `gentar` (silent default, both arenas
  indistinguishable on a shared bench-host — docs say set it, nothing
  warns); single leading letter ok; `gentar-1a` ok; 24 chars exactly ok
  end-to-end; 25 refused. Rule drift in finding 4.
- **Honest coexistence:** two whole identities on one host work — A and
  B both green, spans in distinct volumes, distinct sandbox prefixes,
  no cross-talk.
- **Silent race:** README's OrbStack claim verified live (native server
  answered through a "successful" publish).
