# gentar v0.10.1

A patch release on the 0.10 line, with one engine fix. On the local tier,
the bench-host check for stored sbx secrets refused every suite of a run
that forwarded `ANTHROPIC_API_KEY`. The scenario schema and the exit-code
contract are unchanged.

## What changed, and why

### The sbx secrets check runs in a clean environment

**Problem.** Before it creates a bench, the engine runs `sbx secret ls` on
the bench host. If sbx holds stored secrets, the engine refuses the host with
exit 2, because sbx's credential proxy would hand those secrets to every
sandbox, whatever credentials the run forwarded. The call inherited the
caller's environment. On the local tier (`GENTAR_BENCH_HOST=local`: the arena
runs on the bench host) that is the coordinator's environment, which holds
the provider keys the run forwards. With `ANTHROPIC_API_KEY` set, sbx 0.39
answers

```

Note: 1 additional environment variable found. Run `sbx setup` to review and import.
```

where it would otherwise say "No secrets found". The check counted that line
as a stored secret, and every suite was refused before any bench existed.
Two kinds of run were not affected:

- runs that forwarded `ANTHROPIC_AUTH_TOKEN` instead, or no key;
- runs on the ssh tier, unless the bench user's own login environment held
  such a key.

**Change.** The check runs under `env -i` and passes only what sbx reads to
find its config, state and keyring. The set was measured with sbx 0.39.0 by
tracing `sbx secret ls` with each candidate pointed at an empty directory:

| Variable | Measured |
|---|---|
| `HOME` | required: without it sbx panics (`$HOME is not defined`) and exits 2, and the check refuses ("could not check") |
| `XDG_CONFIG_HOME` | moves sbx's settings and store |
| `XDG_STATE_HOME`, `XDG_CACHE_HOME`, `XDG_DATA_HOME` | move its state, cache and data |
| `XDG_RUNTIME_DIR`, `DBUS_SESSION_BUS_ADDRESS` | read for the session bus (its keyring) |
| `PATH` | not read by sbx; lets `env` find a bare `sbx` |

- Each variable is passed only when it is set.
- The same line runs on the ssh tier, where the bench user's login shell
  expands it.
- Output handling is unchanged. Anything other than "No secrets found"
  refuses, and the refusal reports a count of lines, never the listing.
- `GENTAR_SBX_SECRETS=allow` keeps its meaning. This fix does not need it.

## Upgrade, for adopters

1. **Re-pin the kit to `v0.10.1`.** Copy `gentar/run.sh` from the tag,
   byte-identical; `--check` compares it against the pinned engine. Its one
   change is the engine pin, `REF=${GENTAR_REF:-v0.10.1}`. The other kit
   files (`gentar/plan.py`, `gentar/dryrun.py`, `gentar/release-gate.sh`,
   `gentar/mirror.sh`, `.github/workflows/gentar-arena.yml`) are unchanged
   from v0.10.0.
2. **No scenario, policy or workflow change.**
3. **v0.11.0 has the same check.** Moving to v0.11.0 does not fix this. The
   fix is also on `main` for the next minor release.

## Not live-proven in this release

- The variable set was measured against sbx 0.39.0 only. If a later sbx
  finds its store through a variable not in the list, the check would read
  the default location. Re-measure when the bench host's sbx is upgraded.
- The refusal was reproduced on a bench host by hand. The fix is proven by
  unit tests that drive the real local-tier path with a stand-in `sbx`. The
  live proof is a phase 2 on v0.10.1 that forwards `ANTHROPIC_API_KEY`.
