# gentar v0.10.0

gentar can now test a PUBLIC repository without a self-hosted runner on it, a subject's own
secrets reach the suites that need them by name, and credential values no longer travel on a
command line or into reports and spans. gentar itself moves to Apache-2.0, and its own bench
suites move to a private mirror. Several of these changes come from the ground-up review of
2026-10-19 (Gemini 4 Argon, GPT 6.1 Sol and Claude, cross-examined).

## What changed, and why

### Credential values never ride a command line, an error, a report or a span (#80)

**Problem.** Env values went onto command lines: `export K='v'` in the `sbx exec … sh -lc`
argv for oracle steps, and `env K=v` in the pty's `sbx exec -t` line over ssh. tart and daytona
did the same. Any account on the bench-host can read argv through `/proc`. A timeout's error
text is that argv, and it went into the report (left world-readable), the spans and the CI log.
The osb tier typed its pty command into a shell, which echoed it.

**Change.**
- **Over stdin, never a command line.** Every env var is written into an owner-only file
  inside the bench, over stdin, in an exec of its own (`sbx exec -i`). That exec reports the
  absolute path it used. The command reads the file into an unexported shell variable,
  deletes it, and only then applies it, so an env that sets `HOME` cannot strand the file.
  Only the terminal size stays on the command line. A name that is not a shell identifier is
  refused.
- **Timeouts.** A timeout names the operation (`sbx exec`), never the argv. It is raised so
  the original is not even its exception context.
- **Scrubbing.** The run's scrubber (bench identity plus the declared credentials' values)
  runs over the whole report, the run's error text in the CI log, and every local span row.
- **Reports.** Written `0600` from the first byte. When the coordinator runs as root, each is
  handed to the report directory's owner through the open descriptor. The kit's staged copies
  are owner-only too.
- **osb.** The tier refuses a driver scenario that forwards any env (`credentials` or
  `pass_env`), before any bench (exit 2). It is not a 1.0 tier.
- **Run id.** Driver sessions now also get `GENTAR_RUN_ID`, so the gate's scripted suites
  exercise the same path.

### `[secrets] route`: a subject's own secrets reach its suites by name (#79)

**Problem.** A suite that needs a secret the kit does not wire, such as a read key for the
subject's own service, had no route. The kit workflow passes only `ANTHROPIC_*`,
`TYPESAFE_API_KEY` and the bench secrets, so the suite was skipped in CI. Adding the secret to
the workflow broke the kit's byte-identity check.

**Change.**

```toml
[secrets]
route = ["SUBJECT_READ_KEY"]   # up to 8 repository secrets
```

- **The workflow stays byte-identical.** Its bench job has eight fixed slots, each looking up
  one declared name.
- **One suite at a time.** `run.sh` clears the slots first. It exports a routed name only
  around the coordinator of a suite that declares it (`credentials` or `pass_env`), and takes
  it back when that suite ends. A routed name set by hand, with no slot (a developer's shell, a
  runner's environment), goes the same one way, never to every suite.
- **Never printed, always scrubbed.** Values are redacted from the published reports, and the
  coordinator scrubs them from its own reports, spans and error text too, a `pass_env`
  declaration included: the kit names the routed secrets it exports in `GENTAR_REDACT_NAMES`
  (names only). `gentar/run.sh --route` prints names and their state, never values.
- **Refused names.** The kit's own names, GitHub's and the runner's are refused, as are bash's
  read-only variables and names that steer a shell, the loader or libc (`GLIBC_TUNABLES`,
  `MALLOC_*`), the locale (`LC_*`, which ssh's default `SendEnv` also carries), git, ssh,
  docker, python, node, perl, ruby or java.

### The arena mirror: phase 2 for a public repository, with no self-hosted runner on it (#81)

**Problem.** A self-hosted runner registered to a public repository can be reached by a fork's
own workflow, and that runner holds the bench key.

**Change.** `[arena] bench = "mirror"` with `mirror = "owner/name"`.
- **Public side.** The public repository runs the kit's public variant workflow: plan and
  checks only, GitHub-hosted, no self-hosted job.
- **Private side.** A private mirror (`subject-template/mirror/arena/`) pulls the public
  repository and runs phase 2 on its own runner. `verify-ref.sh` admits only commits reachable
  from the default branch or a `v*` tag, and branch heads only when the mirror's own variable
  allows it. `refs/pull/*` is never fetched.
- **Bounded secrets.** The mirror hands a commit only the secrets on its allowlist, narrowed
  by the commit's own route.
- **Status back.** The result returns as the commit status `arena/phase2`.
  `gentar/mirror.sh dispatch <sha>` runs, waits by polling (any token kind) and posts it,
  unless the mirror run posted it itself. `[phase2] evidence = "status"` makes the release gate
  require it on exactly the release sha, linking a run of that mirror by its run number; that
  evidence needs `[arena] mirror` set, so no other status of the same name can prove a release.
- **A phase 2 that skipped a suite is not green.** The sweep writes the suites it skipped to
  `gentar/reports/sweep-skipped.txt`. The mirror's bench job fails on any of them, so the
  status is a failure naming them, and no `phase2-green` marker keeps the schedule from
  sweeping the commit again (review finding A1).

### The kit's CI jobs do not leave SSH keys behind on a self-hosted runner (#71)

- Keys are written under `umask 077`, and stale ones are removed when a job starts.
- The clone key is removed right after the suites.
- The teardown removes the bench key through a shell trap, under a time limit, before the
  reports upload. A cancelled run's `always()` steps get five minutes in all.

### Local bench mode on rootless Docker (#83), and the workspace root over SSH (#82)

- **Rootless Docker (#83).** `bin/docker-identity` asks the daemon the run actually uses
  whether it is rootless:
  - rootless: the coordinator runs as 0:0, which there is the user;
  - rootful: it runs as the user's own uid, never 0:0;
  - cannot tell: local mode refuses rather than guess.
  osb-server mounts the checked daemon's socket. `bin/arena` reads `GENTAR_BENCH_HOST` the way
  `run.sh` and the coordinator do, spaces and quotes stripped.
- **Workspace root (#82).** `GENTAR_BENCH_WORKSPACE_ROOT` now reaches the coordinator in SSH
  mode too, so the coordinator and `bench-reap` agree on the workspace root.

### gentar's own CI and license

- **Hosted-only public CI (#77, #78).** gentar's public workflow is GitHub-hosted only. Its
  bench suites run in the private mirror `agent-realm/gentar-arena`, after merge, on commits
  reachable from `main` or a `v*` tag. A release is proven by the mirror's gate on the release
  commit before tagging.
- **License (#73, #74).** MIT to Apache-2.0, from this release. Every byte-identical kit file
  carries a two-line SPDX header.
- **Bench hosts (#75, #76).** `bin/bench-host-provision` builds an Ubuntu 24.04 bench host with
  an isolated account and rootless Docker. sbx's first-run wizard on a fresh bench account is
  named, not guessed at.

## Upgrade, for adopters

1. **Re-pin the kit to `v0.10.0`.** Copy these files from the tag, byte-identical. `--check`
   compares each one against the pinned engine:

   | Kit file | Changed in v0.10.0 |
   |---|---|
   | `gentar/run.sh` | pin; `[secrets] route`; `sweep-skipped.txt`; owner-only staged reports; local mode reads `bin/docker-identity` |
   | `gentar/plan.py` | `[secrets]`, `[arena]`, `[phase2] evidence` |
   | `gentar/release-gate.sh` | `evidence = "status"` |
   | `gentar/mirror.sh` | new (mirror mode only) |
   | `gentar/dryrun.py` | the SPDX header only |
   | `.github/workflows/gentar-arena.yml` | key hygiene, eight secret slots |

   Every kit file now starts with the two-line SPDX header; keep it. `gentar/policy.toml` and
   `gentar/README.md` are your own: do not overwrite them. Compare them with the kit's
   templates, which document the new optional tables (`[secrets]`, `[arena]`,
   `[phase2] evidence`), and adopt what you need.
2. **A public repository:** follow `docs/guides/public-repo-arena.md`. The public variant
   workflow replaces the kit's, the mirror gets `subject-template/mirror/arena/`, and the policy
   gets `[arena] bench = "mirror"` and `[phase2] evidence = "status"`.
3. **A subject secret:** declare it in the suite, add it to `[secrets] route`, and store it as
   a repository secret under the same name.
4. **Exit codes and schema:** the exit-code contract is unchanged. The scenario schema is
   unchanged; strict keys come in a later minor release.

## Not live-proven in this release

- A real provider key end to end through the new env-file path. The path itself is proven
  live. gentar's own mirror gate, from #80's merge on (run 39809487553), passes the run id
  through it on the sbx bench, and both the oracle and the pty suites pass.
  A provider key would take the same path, but no gate suite uses one. The provider-key suites
  run only where a key is configured.
- The mirror workflow and `mirror.sh` against a real mirror and a real `gh`: tested against
  fixtures. The first live run is the first adopter's cutover.
- The tart, daytona and osb tiers, which are not 1.0 tiers.

## Known limits

From the ground-up review, not fixed here and planned before 1.0:
- **A1, outside mirror mode.** A default `evidence = "job"` release gate still accepts a
  sweep that skipped suites. The fix, a sweep manifest with `[phase2] require = "all"`, was
  decided on 2026-10-22 and comes in the next minor release.
- **A2-A4.** Unknown scenario keys are still accepted. The agent's own exit status is not
  checked. A quarantined suite exits 0 run directly and 1 through the kit. All three fixes
  are built and wait for the next minor release.
- **D4.** The report directory is still opened to 0777, so a host user can clean root-owned
  artifacts. Fixed right after this release.
- **The report's subject can read `«redacted:GENTAR_BENCH_USER»`.** The run's scrubber now
  covers the whole report, including the bench account's name. When that name equals the
  subject (both are `arena` by default), the subject field is redacted too. Nothing leaks;
  the field just loses its value. Fixed right after this release.

## Right after this release

Not in this release; next, in this order of urgency:
- **D4**: the report directory's 0777 (above).
- **The redacted subject** (above).
- **hidepid on gentar's own bench hosts.** `/proc` on the ryzen bench VMs is mounted without
  `hidepid`, so every account there can list every process. Since this release no credential
  value rides a command line, but the mount option is still the second line of defence. A
  host change, for the pilot and AK47.
