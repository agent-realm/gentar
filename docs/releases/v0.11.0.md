# gentar v0.11.0

gentar's verdicts mean more in this release. A misspelled scenario key is refused instead of
silently weakening a test. The driven program's exit status counts. A quarantined suite reads
"not run" everywhere instead of pass in one place and fail in another. A failed turn leaves a
snapshot of what the pilot saw. Most of this comes from the ground-up review of 2026-10-19
(findings A2, A3, A4, D4).

**Breaking:** the scenario schema is closed. A suite with a stray or misspelled key that loaded
on 0.10.x is refused (exit 2) on 0.11.0, with the closest allowed key named. A driven program
that ends with a non-zero status now fails its run. See "Upgrade, for adopters".

## What changed, and why

### The scenario schema is closed (#86)

**Problem.** A misspelled key loaded, and the scenario ran a weaker test that still passed.
`contain = "x"` in `[[verify.files]]` became a bare existence check. A `[[verify.command]]`
table (singular) was dropped without a word, leaving "0/0 assertions passed" (A2).

**Change.**
- Every table and key the engine does not read is refused, per turn type too (`send` on an
  `expect` turn), with the closest allowed key named:
  `unknown key(s) 'contain' (did you mean 'contains'?)`.
- An array of tables written with single brackets (`[verify.files]`) is refused the same way.
- The dry-run uses the engine's parser, so it refuses such a suite too.
- Every scenario in gentar, its examples and the kit template loads unchanged. So do the 68
  distinct scenario files in the known adopters' checkouts.

### The driven program's exit status counts (#87)

**Problem.** The driver waited for the command to end (EOF) and never asked how it ended. An
agent that crashed, was killed by its own `timeout`, or lost its ssh after writing half the
work could still pass on the files it left (A3).

**Change.**
- After the last turn, the driver reaps the command. A non-zero exit or a death by signal
  fails the run, and the message names the status: `timeout`'s 124, ssh's own 255 on the ssh
  tiers, a signal by name.
- Endings gentar causes are not failures: a last turn that presses ctrl-c (SIGINT counts only
  when ctrl-c was actually typed), the danger gate's abort, teardown, the deadline.
- A goal pilot's `done` does not wait for the program. If the program already ended on its
  own, its status counts.

### A quarantined suite: one outcome, never a pass (#88)

**Problem.** `GENTAR_QUARANTINE` wrote no report. Run directly, the suite exited 0 with nothing
to read. Through the kit, `run.sh`, which expects a report from every outcome, failed it with
"no report written" (A4).

**Change.** The coordinator prints `QUARANTINED [<suite>]: not run` and writes a report with
verdict `skip (exit 0)`, sharing the skip span's run id. The kit reads that verdict, keeps the
exit code at 0 (a known flake must not turn a run red), and ends with
`run summary: N suite(s) quarantined, not run: …`, also a warning annotation in Actions.

### A failed turn leaves a snapshot (#61)

**Problem.** A stuck TUI left only the raw transcript: no screen, no process list.

**Change.**
- When a driver turn fails (a missed pattern, the final wait, the danger gate, a goal pilot's
  end, or the exit status above), the report gets:
  - the rendered last screen;
  - the raw tail of the pty stream, with control characters made visible (a TUI waiting on a
    terminal query shows its `ESC[6n`);
  - the bench's process tree;
  - the output of a new optional `[on_failure] commands` table (strings, or
    `{ command, timeout = 1..600 }`).
- It is captured before the session closes. Every part is scrubbed, including an error that
  stopped a part from being read. The snapshot never replaces the real failure.
- A warning when a driver scenario starts its command under plain `timeout`. GNU timeout puts
  the child in a background process group, so a TUI is stopped by SIGTTIN on its first tty
  read. Use `timeout --foreground`.

### Unnumbered pickers (#62)

`pick` turns recognise Claude Code's unnumbered dialogs (`❯ No, exit` /
`Yes, I trust this folder`). Before, an optional pick was skipped silently and a required one
failed "not reachable".
- An unnumbered cursor line counts only inside an aligned block of options that includes the
  label, so a prompt with typed text (`❯ git status`) never gets keys.
- A slow redraw is waited for, not read as the end of the list.
- A skipped optional pick is named in the report's warnings.

### Report hygiene (#85)

- **The report directory is no longer opened to everyone (D4).** Every report write ran
  `chmod 0777` on the report dir, a host bind, so any account on the host could plant or
  delete reports. The dir is never chmodded or chowned now. The report goes to the dir's owner
  on its descriptor, and `bin/arena run` makes `./out` as the user before compose can.
- **A report's subject reads `arena` again.** v0.10.0 scrubbed the bench account's name from
  the whole report and every exported span. The default account, `arena`, is also the default
  subject, so every subject was blanked for a name the docs publish. That pairing is now
  exempt; any other account name is still scrubbed.

### Smaller fixes

- **Locale-proof sha checks (#89).** `mirror.sh`, `release-gate.sh`, the mirror's
  `verify-ref.sh` and `bin/bench-reap` checked hex with `[0-9a-f]`. Under a shell that orders
  ranges by locale (macOS's bash 3.2 with `en_US.UTF-8`), uppercase A–E passed. The sixteen
  digits are spelled out. Linux mirrors and runners (bash 5) were not affected.
- **`GENTAR_CI_RUNNER` docs (#59).** On GitHub Free, an organisation variable reaches public
  repositories only. Without it, `plan` falls back to `ubuntu-latest` and `checks` to every OS
  in `[phase1] os`. The kit README's list of secrets and variables is complete, held by a test.

## Upgrade, for adopters

1. **Check your scenarios against the closed schema first.** Run
   `GENTAR_REF=v0.11.0 gentar/run.sh --check`: it dry-runs every suite with the pinned engine's
   parser. A refusal names the file, the key, and the closest allowed key. Fix each, then
   re-pin for good.
2. **Check how your driven programs end.** A suite whose program exits non-zero after its last
   turn now fails. End such programs with a last `key` turn pressing ctrl-c, or make them exit
   0. A headless command under `timeout` that hits its limit fails with 124.
3. **Re-pin the kit to `v0.11.0`.** Copy these from the tag, byte-identical:

   | Kit file | Changed in v0.11.0 |
   |---|---|
   | `gentar/run.sh` | pin; reads a quarantined suite's `skip` verdict and lists it in a run summary |
   | `gentar/release-gate.sh` | locale-proof sha check |
   | `gentar/mirror.sh` | locale-proof sha check (mirror mode only) |
   | `mirror/arena/verify-ref.sh` | locale-proof sha check (your private mirror's copy) |

   `gentar/plan.py`, `gentar/dryrun.py` and the kit workflows did not change. `gentar/README.md`
   and `gentar/policy.toml` are your own; the kit's README documents `[on_failure]`.
4. **Optional:** add `[on_failure] commands` to a driver suite whose failures are hard to read.

## Not live-proven in this release

- **The exit-status check with real agents.** The mirror's scripted suites prove it with
  scripted programs (gate runs 39863580570 and later): a clean exit passes, and the danger
  gate's abort passes. `agent-pty-smoke`, where claude exits after ctrl-c ctrl-c, runs only
  where a provider key is configured.
- **Unnumbered pickers against a live Claude Code dialog.** Tested against rendered fakes. The
  first live use is an adopter's onboarding suite.
- **A failure snapshot from a real stuck TUI.** No gate suite fails, so none has produced one;
  every part is unit-tested.
- **`timeout --foreground` in `agent-pty-smoke`.** Unverified until its next dispatch.
- **Quarantine through the mirror.** The mirror sets no `GENTAR_QUARANTINE`; unit-tested only.
- **A real provider key end to end**, as in v0.10.0.

## Known limits

Planned before 1.0 (the path-to-1.0 plan; both design decisions made on 2026-10-22):
- **The outcome model.** Exit 3 = inconclusive is coming. Until then, an infrastructure error
  is exit 1, like a product failure, and an interrupted run can still write a pass (A6, B1).
- **A1 outside mirror mode.** A default `evidence = "job"` release gate still accepts a sweep
  that skipped suites. The sweep manifest with `[phase2] require = "all"` comes in the next
  minor release.
- **Still open from the review:**
  - builtin-name shadowing and assertion quoting (A5, A9: open as #90);
  - subject staging and path containment (C2, C3);
  - docs that contradict the code (D3);
  - the kit's own TOML reading (A7);
  - gate suites that cannot fail (A8);
  - concurrent runs (B3);
  - the runner trust boundary (C4).
- **gentar's own bench hosts:** process command lines are visible across accounts (no
  `hidepid`). It was tried and dropped: it breaks rootless Docker's container start. Mitigated
  by v0.10.0's "no credential on a command line" and by single tenancy.
