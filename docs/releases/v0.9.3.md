# gentar v0.9.3

A suite that only a bench can prove can now say so, and the kit's CI jobs no
longer fill a self-hosted runner's `/tmp`. Both changes came from the first
two adopters that run their own arenas (memhouse, cockpit).

## What changed, and why

### `[scenario] bench_only = "<why>"`

**Problem.** Phase 1 (`gentar/run.sh --check`) dry-runs every suite on the
CI host, with no bench. memhouse's `memhouse-house` suite deploys a
ClickHouse house through the bench's own Docker. The dry-run cannot do that,
and it failed:

- On a GitHub-hosted runner, the suite's verify commands ran without the
  house ("cannot open ~/.memhouse/env"). Every memhouse pull request would
  carry a red check.
- On a host that has Docker, the dry-run deployed a REAL house on the host
  and left it there: a container, a volume and a background process. On the
  arf bench host it also collided with the engine's own ClickHouse on port
  8123.

**Change.** A suite names why only a bench can prove it:

```toml
[scenario]
name = "memhouse-house"
bench_only = "deploys a ClickHouse house through the bench's own Docker"
```

- The dry-run reports it `UNVERIFIED (bench only: <why>)` and never prepares
  or runs it. The marker is read before the full schema check, so even a
  suite with another error is never prepared; such a suite fails.
- The reason is required. An empty or non-string value is refused when the
  suite is parsed.
- The arena (phase 2, on a bench) runs the suite as before. The coordinator
  ignores the key.
- `GENTAR_DRYRUN_BENCH_ONLY=run` runs the suite anyway, on a host that has
  what the reason names.

### CI temp files go to the job's own temp dir

**Problem.** On a self-hosted runner, `/tmp` is shared and nothing cleans
it. The kit's dry-run keeps a failing suite's scratch home in `/tmp` "for
inspection", and a suite's own `mktemp` steps add more on every run. A
runner container's in-memory `/tmp` filled with 7.4 GB of leaked test dirs
(2026-10-07), and the runner went offline.

**Change.** The kit workflow's `plan`, `checks` and `bench` jobs (the jobs
that can run on a self-hosted runner) start with:

```yaml
- name: temp files into the job's temp dir
  run: echo "TMPDIR=$RUNNER_TEMP" >> "$GITHUB_ENV"
```

The runner empties `RUNNER_TEMP` after every job. Two paths stay fixed on
purpose and do not read `TMPDIR`: the arena's cross-runner lock
(`/tmp/gentar-locks`) and the bench workspace root (`/tmp/gentar-workspaces`).

### A dry-run suite that does not parse

A suite whose TOML cannot be read, or that fails the scenario schema, is now
reported as `FAILURE (does not parse: …)`. The sweep goes on to the next
suite. Before, the parse error ended the whole dry-run with a traceback, and
every later suite went unchecked. Such a suite is also never prepared:
`prepare()` runs only for a suite that parses.

### A kit comment, reworded

A comment in `run.sh` contained a `git describe --tags` literal with no
`--match` pattern. Tag-hygiene scans in adopting repos (kommander-playbook's
`version-tag-resolution.sh`) matched it. The comment now says the same thing
without the literal. The code already used `--match 'v*'`.

## The `--check` guard that is lifted

Phase 1 no longer fails a suite that declares `bench_only`. It reports the
suite as UNVERIFIED, with its reason, and exits 0 for it.

Phase 1 still fails on:

- any other suite that fails its dry-run;
- a `bench_only` key that is empty or not a string (a parse refusal);
- kit drift, policy errors, and every other check it made before.

A plain dry-run (`python3 gentar/dryrun.py`, without
`GENTAR_DRYRUN_UNVERIFIED=ok`) still exits non-zero for a `bench_only`
suite: "not proven here" never reads as a pass. A `bench_only` suite is
proven only by the arena, and the release gate still requires its phase-2
result.

## Upgrade, for adopters

1. **Re-pin the kit to `v0.9.3`.** Copy these files from the tag,
   byte-identical. `gentar/run.sh --check` verifies drift for the kit files
   (`run.sh`, `dryrun.py`, `plan.py`, `release-gate.sh` and the workflow);
   `gentar/README.md` is documentation and is not checked, but copy it too:

   | Kit file | Changed in v0.9.3 |
   |---|---|
   | `gentar/run.sh` | the pin (`GENTAR_REF` default `v0.9.3`), a comment |
   | `gentar/dryrun.py` | `bench_only`; a suite that does not parse is a FAILURE and the sweep goes on |
   | `gentar/README.md` | the pin, the `bench_only` paragraph |
   | `.github/workflows/gentar-arena.yml` | the `TMPDIR` step in three jobs |

   `plan.py`, `release-gate.sh` and `hooks.py` did not change.
2. **Optional: add `bench_only` with a reason** to each suite that deploys a
   service through the bench's Docker, or otherwise needs a bench to run at
   all. The key is additive. An engine before v0.9.3 ignores it, so a suite
   may carry it before the re-pin, but phase 1 honours it only from v0.9.3.
3. **Nothing else to migrate.** The scenario schema and the exit-code
   contract (0 pass, 1 fail, 2 refusal) are unchanged.

## Cleanup note: `/tmp/dryrun-home-*`

A self-hosted runner that ran the kit's `checks` job before v0.9.3 may still
hold leftovers in `/tmp`. The fix stops new ones but does not remove old
ones. After the re-pin, as the runner's user, remove the dry-run homes once:

```sh
find /tmp -maxdepth 1 -name 'dryrun-home-*' -user "$(id -un)" -mmin +60 -exec rm -rf {} +
```

`-mmin +60` skips a job that is running now. A suite's own `mktemp` dirs
(`/tmp/tmp.*`) cannot be told apart from other programs' files by name.
Look at them before you remove any.

## Known limits

- **`bench_only` is a declaration.** Phase 1 trusts the reason it gives.
  Review the key like code: a suite marked `bench_only` gets no bench-free
  run of its shell or its assertions. It must still parse: a schema error,
  or an empty reason, fails phase 1.
- **`[scenario]` still accepts unknown keys without a word.** A misspelled
  `bench_only` is ignored by every engine. Making the table strict could
  break existing suites, so it needs its own change.
- **`TMPDIR` covers the kit's jobs only.** An adopter's other workflows on the
  same self-hosted runner need the same line (cockpit added it to its own
  CI jobs).
- **Public subject repositories.** A public repo must not reach a
  self-hosted arena runner. The design for public subjects (a private mirror
  runs phase 2) waits for a decision, and the kit has no support for it yet.

## Engine CI

gentar's own CI gains one job, `unit-checkout`. It runs the whole unit suite
on the checkout, on a GitHub-hosted runner with read-only permissions and no
secrets. Until now the unit tests ran only inside the coordinator image
build, which has no `subject-template/`, so every test that reads the kit was
skipped in CI. Its first run caught a test that only passed inside the image.
