# d3-neighbor — the concurrent arena on a shared bench-host

Played the second team: stood up MY gentar arena on this Mac while other
gentar stacks ran against the same bench-host VM 142, and studied what the
shared host does to two arenas at once.

## What I did (in character)

1. Starting state: docker context `orbstack`; ssh to 10.10.10.52 OK; my
   ports 18135/14325 free. `sbx ls` on 142: "No sandboxes found."
   A sibling drill arena's compose project (`plato-s2-b1-d1-*`) was live
   on this Mac holding host 8123 (localhost) and 4318 (all interfaces).
2. Wired my arena: `.env` from `.env.example` plus
   `GENTAR_CLICKHOUSE_HOST_PORT=18135`, `GENTAR_OTELCOL_HOST_PORT=14325`;
   exported `GENTAR_BENCH_KEY_FILE`; `COMPOSE_PROJECT_NAME=plato-s2-b1-d3-nb`.
   `docker compose config` verified 18135/14325 published, no host
   8123/4318. `docker compose build coordinator` exit 0.
3. Ran `docker compose run --rm -e GENTAR_KEEP_BENCH=1 coordinator run
   otlp-selfreport` — exit 0, report `report-gentar-20260901-235925-216868.md`.
   KEEP_BENCH held my sandbox live for the neighbor observation.
4. Observed the live two-arena window (finding 1): my stopped sandbox and
   a neighbor's RUNNING sandbox side by side in one `sbx ls`, no field
   telling them apart. Ownership of mine was decidable only because my
   own report names the run_id.
5. Telemetry attribution checked: my stack's own ClickHouse held exactly
   one run_id (`gentar-20260901-235925-216868`) — 9 harness spans in
   `gentar.spans`, 1 agent self-report span in `gentar.otel_traces`, join
   on `gentar.run_id` holding. Nothing of the neighbor's landed in my
   telemetry (each arena has its own compose volume; the OTLP relay is a
   drop-file read by MY coordinator over MY compose network — the host
   port publish is not on the arena's own path).
6. Read the teardown path (`coordinator/gentar/benchhost.py` `rm`):
   `sbx rm <name> --force` + `rm -rf <workspace_root>/<name>`, both
   exact-run_id scoped — no glob, no prefix sweep, no overreach path.
7. Removed MY sandbox by exact name (`sbx rm gentar-20260901-235925-216868
   --force` + workspace rm) — ownership proven by my report. The
   neighbor's sandbox disappeared on its own before this (their teardown
   completed; observed going from `running` to absent between two polls,
   ~00:01:45 UTC). I never touched it.
8. Teardown: `docker compose ps` (only my three containers, ports
   18135/14325), `docker compose down -v --remove-orphans` exit 0; ports
   freed; `sbx ls | grep gentar-` → bench-host-clean. A new neighbor's
   two live stacks (`plato-d2-stacka` 18133/14323, `plato-d2-stackb`
   18134/14324) survived my teardown untouched.

## Non-findings (observed, graded against the pre-set categories)

- neighbor-blocking: NOT observed. The port knobs worked; my run exited 0
  with the neighbor arena live on the same bench-host; concurrent
  sandboxes coexisted without interference.
- teardown-overreach: NOT observed from the product. Teardown is
  exact-name scoped; my teardown left the concurrent d2 stacks and the
  neighbor sandbox untouched.

## Sequence note

One live neighbor at a time, sequential, no load — exactly one suite run
from my side, one sandbox, one removal. The d1 stack I observed on 8123/
4318 and the d2 stacks on 18133/18134 were recorded verbatim and never
modified.
